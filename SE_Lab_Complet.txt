1. SRS (SOFTWARE REQUIREMENTS SPECIFICATION)

Exam format: - Abstract - 10 Functional Requirements - 10 Non-Functional
Requirements

Abstract: Short description of the system, its purpose, users, and main
features.

Functional Requirements (FR) = WHAT the system does. Examples: 1. User
registration. 2. User login. 3. Update profile. 4. Search
records/services. 5. Display results. 6. Submit a request. 7. Validate
input. 8. Store information. 9. Send notifications. 10. Admin manages
records.

Non-Functional Requirements (NFR) = HOW WELL the system works.
Examples: 1. Performance – pages/results load in acceptable time. 2.
Security – protect passwords and sensitive data. 3. Reliability –
operate consistently. 4. Availability – accessible when required. 5.
Usability – easy-to-use interface. 6. Scalability – support increasing
users/data. 7. Maintainability – easy to update. 8. Compatibility – work
on supported browsers/devices. 9. Accuracy – correct processing and
information. 10. Backup and recovery – data can be backed up and
restored.

2. UML DIAGRAMS AND STARUML

Exam requirement: draw the requested diagram on paper AND create it in
StarUML.

StarUML steps: 1. Open StarUML. 2. File -> New. 3. Right-click Model in
Model Explorer. 4. Add Diagram. 5. Choose the required diagram. 6. Drag
elements onto the canvas. 7. Connect them using relationships. 8. Add
names/attributes/methods/messages. 9. Save.

USE CASE DIAGRAM - Actors outside the system boundary. - Use cases as
ovals inside the boundary. - Associations connect actors to use cases.
Example: Campus Event Management Actors: Student, Faculty, Admin. Use
cases: Login, View Events, Register for Event, View Schedule, Receive
Notifications, Create Event, Update Event, Cancel Event, Manage
Participants, Generate Reports.

CLASS DIAGRAM - Class rectangle has class name, attributes, methods. -
Visibility: + public, - private, # protected. Example Hospital
Management classes: Patient, Doctor, Appointment, MedicalRecord, Bill.

SEQUENCE DIAGRAM - Shows object interactions in time order. -
Participants at top; lifelines downward; messages are horizontal
arrows. - Time flows top to bottom. Example Food Ordering participants:
Customer, Food Ordering System, Payment Gateway, Restaurant. Possible
messages: login(), loginSuccess(), viewMenu(), displayMenu(),
placeOrder(), processPayment(), paymentSuccess(), sendOrder(),
confirmOrder(), orderConfirmation().

COMPONENT DIAGRAM - Shows high-level software components and
dependencies. Example Online Gaming: User Interface, Authentication,
Game Engine, Player Management, Leaderboard, Database.

3. GIT AND GITHUB

Git = distributed version control system. GitHub = online platform for
hosting Git repositories and collaboration.

Initial configuration: git –version git config –global user.name “Your
Name” git config –global user.email “your@email.com” git config –list

Create repository: mkdir SE-Lab cd SE-Lab notepad README.txt git init
git status git add README.txt git commit -m “First commit”

Clone: git clone REPOSITORY_URL cd PROJECT_FOLDER

Status and history: git status git diff git diff –staged git log git log
–oneline git log –oneline –all –graph

Stage and commit: git add . git add filename git commit -m “Commit
message”

Branches: git branch git branch feature git checkout feature git
checkout -b feature git switch -c feature

Merge: git checkout main git merge feature

Rebase: git checkout feature git rebase main

Stash: git stash git stash list git stash apply git stash pop git stash
drop

Undo: git reset –soft HEAD~1 git reset –mixed HEAD~1 git reset –hard
HEAD~1 git revert COMMIT_ID WARNING: reset –hard can discard uncommitted
changes. revert creates a new commit that reverses an earlier commit.

Remote: git remote add origin REPOSITORY_URL git remote -v git push -u
origin main git push git fetch origin git pull git branch -r git branch
-a

Viva terms: - Repository: directory/project tracked by Git. - Commit:
saved snapshot of changes. - Staging area: prepares changes before
commit. - HEAD: reference to current commit/position. - origin:
conventional remote name. - Branch: separate line of development. -
Merge conflict: Git cannot automatically combine changes. - .git: hidden
directory containing repository data. - Fork: personal copy of another
repository on a hosting platform. - Pull request: request to merge
proposed changes. - .gitignore: lists files Git should ignore.

4. NAGIOS

Nagios = open-source monitoring tool for servers, networks, and
services.

Terms: - Host: machine/device being monitored. - Service:
function/resource monitored on a host. - Plugin: program/script that
checks a host or service. - Alert: notification generated when a
monitored state changes. - Nagios Core: monitoring engine. - NRPE:
Nagios Remote Plugin Executor, used for checks on remote systems.

States: OK, WARNING, CRITICAL, UNKNOWN. Architecture: Web Interface ->
Nagios Core -> Plugins -> Hosts/Services.

Install on Ubuntu: sudo apt update sudo apt install -y nagios4
nagios4-cgi nagios-plugins

Start/enable: sudo systemctl enable –now nagios4 sudo systemctl status
nagios4 sudo systemctl enable –now apache2 sudo systemctl status apache2

Useful commands: sudo systemctl start nagios4 sudo systemctl restart
nagios4 sudo systemctl status nagios4 sudo systemctl start apache2 sudo
systemctl status apache2 nagios4 -v /etc/nagios4/nagios.cfg

Dashboard: http://localhost/nagios4 Paths: /etc/nagios4/nagios.cfg
/etc/nagios4/conf.d/ /usr/lib/nagios/plugins/

Validate configuration: nagios4 -v /etc/nagios4/nagios.cfg

5. MAVEN JAVA PROJECT

Maven = build automation and project management tool, commonly used for
Java.

Workflow: 1. Clone repository. 2. Enter project folder. 3. Inspect
pom.xml and project structure. 4. Run Maven commands. 5. Check generated
output in target/.

Commands: git clone REPOSITORY_URL cd PROJECT_FOLDER mvn clean mvn
compile mvn test mvn package

Meaning: - clean: removes previous build output. - compile: compiles
source code. - test: runs tests. - package: creates distributable
JAR/WAR.

Example Java: public class App { public static void main(String[] args)
{ System.out.println(“Metro Management System”);
System.out.println(“Maven Build Successful!”); } }

Example pom.xml essentials: com.metro MetroProject 1.0

For a JAR project, packaging is normally jar (or omitted because jar is
the default). Check BUILD SUCCESS and the generated JAR inside target/.
Run an executable JAR: java -jar target/PROJECT_NAME.jar

Do not change pom.xml blindly. Inspect README, pom.xml, folder
structure, Java version, and packaging first.

6. MAVEN WEB PROJECT (WAR + TOMCAT)

1.  Clone repository and enter project folder.
2.  Inspect pom.xml and confirm it is a web application.
3.  Confirm packaging: war
4.  Build: mvn clean package
5.  Check: ls target/
6.  Copy WAR to Tomcat webapps (Linux example): sudo cp target/.war
    /var/lib/tomcat/webapps/
7.  Restart/check Tomcat (service name may vary): sudo systemctl restart
    tomcat sudo systemctl status tomcat
8.  Open deployed app: http://localhost:8080/CONTEXT_PATH/

Notes: - WAR filename usually determines context path unless configured
otherwise. - Tomcat path, service name, version, and port can differ. -
Use the installation/path available on the exam computer. - Verify the
WAR and deployed application, not only BUILD SUCCESS.

7. JENKINS

Jenkins = automation server used for Continuous Integration and
Continuous Delivery/Deployment (CI/CD).

Initial setup: 1. Open Jenkins URL (example http://localhost:8081; use
actual configured port). 2. Complete initial admin setup. 3. Install
required plugins if needed: Git, Pipeline, GitHub Integration, Pipeline
Stage View, Maven Integration. 4. Manage Jenkins -> Tools: configure JDK
(example JDK17) and Maven (example Maven3).

FREESTYLE MAVEN JOB 1. Dashboard -> New Item. 2. Enter job name ->
Freestyle project -> OK. 3. Source Code Management -> Git -> enter
repository URL. 4. Set branch to /main or /master after checking default
branch. 5. Configure Build Triggers if required. 6. Add build step:
Invoke top-level Maven targets, or Execute shell/Windows batch command:
mvn clean package 7. Post-build Actions -> Archive artifacts:
target/.war or: target/.jar 8. Save -> Build Now. 9. Build History ->
Console Output. 10. Verify BUILD SUCCESS and archived artifacts.

Optional Poll SCM: H/5 * * * *

SCRIPTED PIPELINE (LINUX AGENT) node { stage(‘Checkout’) { git branch:
‘main’, url: ‘REPOSITORY_URL’ } stage(‘Clean’) { sh ‘mvn clean’ }
stage(‘Compile’) { sh ‘mvn compile’ } stage(‘Test’) { sh ‘mvn test’ }
stage(‘Package’) { sh ‘mvn package’ } stage(‘Archive’) {
archiveArtifacts artifacts: ’target/*.war’, fingerprint: true } }

For Windows agents, replace sh with bat.

DECLARATIVE PIPELINE pipeline { agent any tools { jdk ‘JDK17’ maven
‘Maven3’ } triggers { pollSCM(‘H/5 * * * ’) } stages { stage(’Checkout’)
{ steps { git branch: ’main’, url: ’REPOSITORY_URL’ } } stage(’Clean’) {
steps { sh ’mvn clean’ } } stage(’Compile’) { steps { sh ’mvn compile’ }
} stage(’Test’) { steps { sh ’mvn test’ } } stage(’Package’) { steps {
sh ’mvn package’ } } } post { success { echo ’Build completed
successfully’ } failure { echo ’Build failed. Check Console Output.’ }
always { archiveArtifacts artifacts: ’target/.war’, allowEmptyArchive:
true } } }

Important: - tools {} belongs in Declarative Pipeline, not inside
Scripted node {}. - Use correct repo URL and branch from the exam
slip. - Archive target/.jar for JAR projects; target/.war for WAR
projects. - sh is for Unix/Linux agents; bat is for Windows agents.

GITHUB WEBHOOK (IF ASKED) - Jenkins must be reachable by GitHub over the
internet. - A localhost-only Jenkins URL cannot receive GitHub
webhooks. - Example tunnel command: ngrok http 8081 - Configure GitHub
webhook with HTTPS forwarding URL ending in /github-webhook/ - Content
type: application/json; select push events if required.

8. DOCKER

Docker = platform for building, shipping, and running applications in
containers.

Terms: - Image: read-only template used to create containers. -
Container: running/stopped instance of an image. - Dockerfile:
instructions to build an image. - Docker Engine: platform that
builds/runs containers. - Docker daemon: background service managing
Docker objects. - Docker CLI: command-line interface. - Registry:
service that stores images. - Docker Hub: public image registry. -
Volume: persistent storage for container data. - Port mapping: connects
host port to container port.

BUILD AND RUN A MAVEN JAVA JAR 1. Clone and enter repository: git clone
REPOSITORY_URL cd PROJECT_FOLDER 2. Build: mvn clean package 3. Create
Dockerfile in project root: FROM openjdk:17 WORKDIR /app COPY
target/*.jar app.jar EXPOSE 8080 CMD [“java”, “-jar”, “app.jar”] 4.
Build image: docker build -t myapp . 5. List images: docker images 6.
Run container: docker run -d -p 8080:8080 –name mycontainer myapp 7.
Check: docker ps 8. Logs: docker logs mycontainer 9. Open
http://localhost:8080

Caveats: - This assumes an executable JAR and an app listening on port
8080. - For a WAR, use a suitable Tomcat-based approach. - EXPOSE
documents the container port; it does not publish it. - -p
publishes/maps the port to the host.

DOCKER HUB docker login docker tag myapp USERNAME/myapp docker push
USERNAME/myapp

On another system: docker pull USERNAME/myapp docker run -d -p 8080:8080
USERNAME/myapp

USEFUL DOCKER COMMANDS docker –version docker images docker ps docker ps
-a docker build -t myapp . docker run -d -p 8080:8080 –name mycontainer
myapp docker logs mycontainer docker stop mycontainer docker start
mycontainer docker rm mycontainer docker rmi myapp docker inspect
mycontainer docker exec -it mycontainer bash docker login docker tag
myapp USERNAME/myapp docker push USERNAME/myapp docker pull
USERNAME/myapp

DOCKERFILE INSTRUCTIONS - FROM: selects base image. - WORKDIR: sets
working directory. - COPY: copies files into image. - ADD: copies files
and supports additional features such as URL/tar handling. - RUN:
executes a command during image build. - CMD: default command/arguments
when container starts. - ENTRYPOINT: configures main executable. -
EXPOSE: documents the application port. - ENV: sets environment
variables. - .dockerignore: excludes files from build context.

9. DOCKER COMPOSE

Docker Compose = tool for defining and running multi-container
applications using YAML.

Commands: docker compose up -d docker compose down docker compose ps
docker compose logs

Remember: - up -d starts services in background. - down stops/removes
Compose-managed containers and networks. - down -v also removes named
volumes; use carefully. - depends_on controls startup ordering, but does
not necessarily mean a dependency is ready. - Volumes persist data
beyond a container’s lifecycle.

10. KUBERNETES

Kubernetes = open-source container orchestration platform.

Terms: - Cluster: group of machines managed by Kubernetes. - Node:
machine in cluster. - Pod: smallest deployable unit; contains one or
more containers. - Deployment: manages Pods and their desired state. -
ReplicaSet: maintains desired number of Pod replicas. - Service: stable
network endpoint for Pods. - ClusterIP: Service accessible inside
cluster. - NodePort: exposes Service through a port on each node. -
LoadBalancer: exposes Service using an external load balancer where
supported. - kubectl: Kubernetes command-line tool. - Minikube: tool for
running a local Kubernetes cluster. - YAML: commonly used configuration
format.

Start Minikube: minikube start –driver=docker

Commands: kubectl get pods kubectl describe pod POD_NAME kubectl logs
POD_NAME kubectl get deployments kubectl get services kubectl get svc
kubectl scale deployment nginx –replicas=5

Pod states: - Pending: not yet scheduled or started successfully. -
Running: Pod is running. - CrashLoopBackOff: container repeatedly
crashes; Kubernetes waits before restarting. - Completed: container
finished successfully.

Remember: - Pod IP may change when a Pod is recreated. - Service
provides a stable virtual IP/DNS endpoint. - Deployment manages desired
replicas.

11. AWS EC2

AWS = Amazon Web Services, a cloud computing platform. EC2 = Elastic
Compute Cloud; provides virtual servers called instances.

Basic EC2 practical: 1. Open institution-provided AWS Academy Learner
Lab. 2. Start the lab and open AWS Console. 3. Open EC2. 4. Select
Launch Instance. 5. Enter instance name. 6. Choose required
AMI/operating system. 7. Select instance type specified by the
question/instructor. 8. Configure/select required key pair. 9. Configure
network/security group according to task. 10. Review and launch. 11.
Open EC2 -> Instances. 12. Refresh until Instance state shows Running.
13. Show instance details/state to instructor.

Terms: - AMI: Amazon Machine Image; template used to launch an
instance. - Instance: virtual server running in EC2. - Instance type:
defines CPU, memory, networking, and capacity. - Key pair: credentials
used for secure access. - Security group: virtual firewall controlling
inbound/outbound traffic. - Region: geographic AWS area. - Availability
Zone: isolated location within a Region. - EBS: block storage used with
EC2. - Public IP: address used to reach an instance when configured. -
SSH: secure remote login commonly used for Linux. - RDP: remote desktop
protocol commonly used for Windows.

Learner Lab reminders: - Lab sessions can expire; start the lab again
when needed. - Resource access depends on Learner Lab rules and
duration. - Check instance state is Running before presenting. - Save
screenshots of launch and instance details if permitted. -
Stop/terminate resources after demonstration according to lab
instructions. Termination deletes the instance and may delete associated
temporary resources.
